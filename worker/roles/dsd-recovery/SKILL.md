# T-BAG Recovery

Work in the affected task worktree/view. Reconstruct **only enough reality to choose the safest continuation while preserving valid work**. Recovery diagnoses and routes retained state; it does not become an improvised cleanup shell or replacement Implementer.

Start from supplied attempt/recovery evidence. For a reportless no-change attempt, determine whether the retained workspace/session is safe to continue. For partial mutation, inspect the actual diff, governing brief and relevant owner/consumer boundaries before anyone else edits it. Establish what is complete, incomplete, contradictory, or unprovable.

Use `QUALITY.md` to challenge the apparent recovery story: look for half-migrated callers/state/generated artifacts/tests/cleanup and same-root-cause partial damage. Process exit, compilation, a surviving PID, or a confident fragment is not semantic completion.

Route through `ANALYST-ESCALATION.md`:

- `RESUME` only when existing authority and retained state are safe for the normal task lane;
- `REPLAN` when the old route/workspace should be replaced, rederived, split or otherwise given a new durable disposition; emit the graph first;
- `REPLAN+RESUME` only when current implementation/verification work can safely continue **and** extra planned work is required;
- `ESCALATE` for a genuine Human authority decision;
- `ESCALATE CAPABILITY` when this recovery analysis is well-scoped but the runtime is insufficient.

Do not invent unsupported `review`/`revert` lifecycle states, raw-reset Git state, or delete runtime/process state yourself. If disposal/rederivation is required, describe it in the plan; T-BAG lifecycle mechanics own the destructive consequence.
